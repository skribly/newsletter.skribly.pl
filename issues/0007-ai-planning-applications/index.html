AI in the planning office

PlanAssist does the routine checks, an officer decides

On 31 October 2026 Google DeepMind described PlanAssist, a tool built with Gemini for local planning authorities together with the UK government, Google Cloud and Faculty. For routine householder applications it checks the documents, compares them with planning policies and heritage constraints, reviews earlier objections and drafts a report with citations for the officer to edit. In pilots in Barnet, Camden and Dorset it cut the time officers spend on these assessments by up to 58%. It now moves into a 12-month beta with live applications in 15 councils, and if testing succeeds the government plans to offer it to all councils in England in 2027. A qualified planning officer reviews and approves every assessment before any decision is made.

Source: Google DeepMind: Speeding up planning decisions with AI

In brief

The weights of Kimi K3.1 Pro are on Hugging Face

Moonshot AI had promised the weights of Kimi K3.1 Pro by 4 November, and they are now on Hugging Face; the first commit of the repository is dated 2 November 2026. The model has 2.8 trillion parameters, of which 104 billion are active, a context of one million tokens, and reads text and images. The Kimi K3.1-Pro License allows use, changes and fine-tuning, but large providers that offer models as a service need a separate agreement, and very large products must show the model's name. Moonshot recommends vLLM, SGLang or TokenSpeed to run it.

Sources: Hugging Face: moonshotai/Kimi-K3.1-Pro · Hugging Face: commit history

OpenAI models for biology and for security work

On 30 October 2026 OpenAI released GPT-6 Rosalind, which brings specialised biological reasoning and scientific tool use to life sciences research. On 5 November it added GPT-6-Cyber, to investigate a vulnerability, reproduce it in an authorised test environment and verify the fix. Neither model is open to everyone: Rosalind goes to organisations approved for Rosalind Research, and GPT-6-Cyber needs Daybreak Red access and approval.

Sources: OpenAI: API changelog · OpenAI: GPT-6-Cyber

GPT-Image-2.6 edits from your sketches

On 4 November 2026 OpenAI released two image models: GPT-Image-2.6 Sunburst for detailed work and GPT-Image-2.6 Flare for fast iteration. Both can produce SVG and animated GIFs. A complexity setting goes from low to high: high helps with dense text and complex layouts, but can be slower and change more than you asked. New is editing by markup: you draw circles or sketches on a transparent layer and describe the change in words.

Sources: OpenAI: API changelog · OpenAI: Image generation guide

The Ruby SDK for MCP reaches Tier 1

On 30 October 2026 the official Ruby SDK for the Model Context Protocol reached Tier 1, the highest of MCP's three SDK tiers. From version 1.2.0 of the mcp gem it supports the 2026-07-28 specification and passes 100% of the scored conformance scenarios. Tier 1 means support for a new spec version on its release day, triage of issues within two business days and fixes for critical bugs within seven days.

Sources: MCP Blog: The Official Ruby SDK for MCP Reaches Tier 1 · GitHub: modelcontextprotocol/ruby-sdk

CWE-bench v2 asks whether agents can fix security flaws

CWE-bench v2, published by Collinear AI on the Hugging Face blog on 3 November 2026, checks whether an AI agent can find and fix a security weakness in a real open-source repository without breaking what already works. The public set has 100 tasks, each reviewed by hand, covering 91 kinds of weakness (CWEs), and scoring is automatic and reproducible. Of the 11 models tested, the best solved 67.8% of tasks at the first attempt, and even the leader fails 19% of them on every try.

Sources: Hugging Face: CWE-bench v2 · Hugging Face: collinear-ai/cwe-bench

An AI toolbox for European public administrations

On 4 November 2026 the Interoperable Europe portal of the European Commission opened an AI toolbox for public administrations. It gathers reusable open-source tools, examples from European administrations, training for officials, and guidance on the law and on buying AI solutions. It supports the Commission's Apply AI Strategy, which promised a shared repository of reusable tools.

Source: Interoperable Europe: AI toolbox to support public administrations adopting AI

From Skribly

One name for our tools: Skribly

On 4 November three of our tools took the Skribly name. With version 1.0.30 the desktop app is called Skribly Agent, and existing installs keep their settings, tokens, sessions and sign-ins. In Skribly Tracker 0.1.16 the interface and logos say Skribly, and webhooks send X-Skribly headers next to the older ones, so existing receivers keep working. In agent-skills 0.2.5 the tracker id becomes skribly; older names and credentials keep working.

Sources: docs.skribly.pl: Skribly Agent 1.0.30 · docs.skribly.pl: Skribly Tracker 0.1.16 · docs.skribly.pl: agent-skills 0.2.5

One thing to try

Find your workflows that use pull_request_target

On 2 November 2026 GitHub announced that from 2 December 2026 GitHub Actions will block the pull_request_target event by default in public repositories, unless an Actions event policy allows it. The reason: such a workflow runs with the secrets of the base repository, so untrusted code from a fork could steal them. Run grep -rn pull_request_target .github/workflows in your repository. If nothing needs the trigger, keep the default; if a workflow does, allow only that workflow in an event policy.

Source: GitHub Changelog: pull_request_target blocked by default December 2
